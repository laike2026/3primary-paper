# tpc-paper.com 正式站审计与修复记录（2026-10-21）

## 范围与数据路径

正式站有英文、阿拉伯文、俄文、西班牙文四种语言。公开页面包括首页、产品列表与分类、产品详情、应用列表与详情、OEM、制造与质量、公司介绍、品牌、资源与下载、新闻列表与详情、FAQ、联系、隐私及条款。`sitemap.xml` 当前列出 148 个语言页面。后台有总览、产品分类、产品管理、新闻分类、新闻管理、询盘管理、访问分析、数据追踪、搜索表现、媒体库、数据同步、账号权限、操作记录、网站设置。

| 前端操作或内容 | 接口／处理 | 数据来源或去向 | 后台位置 |
| --- | --- | --- | --- |
| 产品筛选、分类、详情 | 公开页面服务端读取 | `content_categories`、`content_products`，媒体资源 | 产品分类、产品管理、媒体库 |
| 新闻浏览 | 公开页面服务端读取 | 仅人工发布的 `content_articles`、`news_categories` | 新闻分类、新闻管理 |
| 下载询价清单 | 语言资源页与 `/downloads/*` | 仓库中的静态文件 | 目前需代码维护 |
| 提交询盘 | `/api/inquiry`，后台通知任务 | `inquiries`、`sync_jobs`、邮件服务 | 询盘管理、数据同步 |
| 已同意访客的页面／产品／文章浏览与联系点击 | `/api/events` | `analytics_events`、`analytics_daily` | 访问分析、数据追踪 |
| 地址和 WhatsApp 点击、表单打开／填写／提交 | 前端事件、`/api/events`；成功提交由服务端确认 | 同上；成功询盘另存 `inquiries` | 数据追踪、询盘管理 |
| 搜索表现 | 登录触发及 `/api/cron/sync`，Search Console API | `sync_jobs`、`search_console_daily` | 搜索表现、数据同步 |
| 每周网站更新提交 | `/api/cron/sitemap`，Search Console API | `sync_jobs`，读取公开站点地图 | 搜索表现、数据同步 |
| 电话、WhatsApp、详细地址、地图 | 公开页面读取 `public_contact` | `site_settings` | 网站设置 |
| Logo、公共邮箱、部分正文、FAQ、静态资料 | 组件／静态文件 | 仓库 | 目前需代码维护 |

后台“访问分析”和“数据追踪”是本站在访客同意后收集的第一方数据，不是 GA4。客户已决定暂不接入 GA4；因此不宣称有 GA4 渠道、会话或国家报表。国家由请求地区标记推断，来源只反映网址的 UTM 参数。

## 已执行检查

- 抓取正式站站点地图的全部 148 个网址：均返回 HTTP 200，具有标题、主标题、规范网址、四种语言及 `x-default` 对应链接；未发现意外 `noindex` 或缺少图片替代文本。
- 检查 `robots.txt`、站点地图、企业及产品内容入口，HTTP、`www` 到 HTTPS 主域的跳转，以及两份语言询价清单下载。敏感文件路径返回 404，未登录的后台统计接口返回 401。
- 对照已确认的首页设计查看桌面和 390px 手机页面；检查手机菜单、联系页表单、产品详情与后台页面。抽样页面没有横向溢出。截图保存在 `output/audit-*-before.png`。
- 逐个打开 13 个后台入口，首次页面打开约 0.9–9.1 秒；复测部分页面约 1.5–7.9 秒。结果是单次实际浏览器观察，混有网络及服务器冷启动时间，不能代表各地区长期性能。原始记录：`output/admin-timings-before.json`。
- 只读核对数据库：6 个已发布产品分类、9 个产品、3 篇人工新闻；审计时没有询盘和近 30 天站内事件。Search Console 曾有成功任务，但当时没有已存报表行。没有为了测试往正式站写入询盘。

## 本次修复

1. 手机菜单增加遮罩、背景滚动锁定、Escape 关闭和键盘焦点循环；桌面产品下拉在焦点离开时关闭。手机联系页隐藏会压住表单的 WhatsApp 悬浮按钮，联系入口仍保留在页面中。
2. 已同意统计的访客进入产品／新闻详情时，记录相应浏览事件；后台明确标注第一方统计口径，接口错误时不再把未知状态显示为零。
3. Search Console 每日同步新增独立的总量行，报表总点击和展现不再由可能受匿名搜索词限制的明细行相加。报表限定当前站点属性，并展示实际覆盖日期、队列和失败情况。
4. 登录和半小时定时任务继续补齐未覆盖日期；最近七天的数据允许 72 小时后刷新，失败任务按现有退避规则重试。同步完成后移除该日过时的明细行。
